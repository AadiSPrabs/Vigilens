# Vigilens: Frontend / Backend Contract

**Status:** DRAFT v0.1, proposed by the frontend (Raakin), awaiting backend confirmation (Aadi)
**Freeze target:** Sat 31 Oct 2026. After this date the shape does not change without both people agreeing.

This document is the single source of truth for what the frontend sends and what it expects back. The frontend is being built against local fixtures that follow this exact shape, so when the real endpoint is ready, switching over is a one-file change (`frontend/src/api/auditClient.js`).

Items marked **[OPEN]** are not agreed yet. Please answer them in Section 8.

---

## 1. Ground rules

| Rule | Detail |
|---|---|
| Coordinates | Normalised **0 to 1**, origin **top-left** (x to the right, y downward). Relative to the **original uploaded image**, not a resized copy. |
| Polygons | Arrays of `{ "x": number, "y": number }`. At least 3 points. Not repeated-closed (do not repeat the first point at the end). |
| Severity | Computed **only** by the backend's deterministic matrix. The frontend renders it and never computes or changes it. |
| PPE status | Exactly one of `"present"`, `"absent"`, `"unknown"`. Use `"unknown"` for occluded or ambiguous PPE. The frontend never converts `unknown` to `absent`. |
| Evidence | Original image plus deterministic polygon overlays. Never generatively edited. Faces are masked by the backend. |
| API keys | Live only on the backend. The frontend holds no Meta keys and makes no Meta calls. |
| Failures | If an audit fails, return an error status (Section 6). Never return a fake or partial "success". |

## 2. Endpoint

```
POST {API_BASE_URL}/audit
```

**[OPEN]** The path `/audit` is a placeholder. Please confirm the real path. The frontend keeps it in a single constant.

CORS: the frontend runs on a Vite dev server (default `http://localhost:5173`). The backend needs to allow that origin during development.

---

## 3. Request

`Content-Type: multipart/form-data` with two parts:

| Part | Type | Description |
|---|---|---|
| `image` | file (`image/jpeg`, `image/png`, `image/webp`) | The original photo. Frontend limit: 15 MB. |
| `zones` | text, JSON string | Operator-drawn zones for this camera (below). |

`zones` JSON:

```json
[
  {
    "id": "zone-1",
    "name": "Crane Zone",
    "hazard": true,
    "points": [
      { "x": 0.10, "y": 0.20 },
      { "x": 0.60, "y": 0.20 },
      { "x": 0.60, "y": 0.80 },
      { "x": 0.10, "y": 0.80 }
    ]
  }
]
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Generated by the frontend, unique within the request |
| `name` | string | Operator-chosen label, e.g. "Crane Zone" |
| `hazard` | boolean | `true` = hazard zone, `false` = restricted-only zone |
| `points` | array of `{x, y}` | 3 or more points, normalised 0 to 1 |

Zones are operator-drawn. The backend must not infer, add, remove or modify zones. An empty array `[]` is valid (the operator chose "Run without zones").

## 4. Response: `200 OK`, `application/json`

```json
{
  "audit_id": "audit-001",
  "image": { "id": "img-001", "width": 1280, "height": 720 },
  "zones": [
    {
      "id": "zone-1",
      "name": "Crane Zone",
      "hazard": true,
      "points": [
        { "x": 0.10, "y": 0.20 },
        { "x": 0.60, "y": 0.20 },
        { "x": 0.60, "y": 0.80 },
        { "x": 0.10, "y": 0.80 }
      ]
    }
  ],
  "persons": [
    {
      "id": "person-1",
      "polygon": [
        { "x": 0.30, "y": 0.30 },
        { "x": 0.45, "y": 0.30 },
        { "x": 0.45, "y": 0.70 },
        { "x": 0.30, "y": 0.70 }
      ],
      "helmet": "absent",
      "vest": "present",
      "zone_id": "zone-1",
      "worst_severity": "Critical",
      "findings": [
        {
          "rule_id": "NO_HELMET_IN_HAZARD",
          "severity": "Critical",
          "message": "Person in Crane Zone without a helmet.",
          "review_state": "needs_human_review",
          "recheck_trace": [
            "Low confidence on first pass (0.54)",
            "Cropped and re-segmented head region",
            "Still no hard hat detected (0.88)"
          ]
        }
      ]
    }
  ],
  "evidence_image": null
}
```

### 4.1 Top-level fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `audit_id` | string | yes | Unique per audit run |
| `image` | object | yes | `id` (string), `width` and `height` (positive integers, pixels of the original) |
| `zones` | array | yes | Echo of the zones sent in the request, same `id`s. May be empty. |
| `persons` | array | yes | One entry per detected person. May be empty. |
| `evidence_image` | see 4.4 | no | **[OPEN]** format not agreed. May be `null` or absent. |

### 4.2 Person fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | yes | Unique within the audit |
| `polygon` | array of `{x, y}` | yes | Person mask outline, normalised |
| `helmet` | `"present"` / `"absent"` / `"unknown"` | yes | |
| `vest` | `"present"` / `"absent"` / `"unknown"` | yes | |
| `zone_id` | string or `null` | yes | The zone the person is in. `null` means outside all zones. |
| `worst_severity` | string | no | **[OPEN]** Highest severity among this person's findings. If absent, the frontend does **not** guess one. It labels each finding separately and keeps the person's outline neutral. |
| `findings` | array | yes | Empty array means the person is compliant |

If a person is in more than one overlapping zone, please pick one `zone_id` and tell us the rule you use. **[OPEN]**

### 4.3 Finding fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `rule_id` | string | yes | Stable identifier from the severity matrix, e.g. `NO_HELMET_IN_HAZARD` |
| `severity` | string | yes | Expected values: `"Critical"`, `"Medium"`, `"Low"`. See note below. |
| `message` | string | yes | Plain-language Muse explanation, shown **verbatim** on the report. Plain text, no markdown or HTML. |
| `review_state` | `"auto"` / `"needs_human_review"` | yes | `needs_human_review` = still uncertain after the re-check, escalated to a person |
| `recheck_trace` | array of strings | yes | Short human-readable steps of the re-check. May be empty. Shown in an expandable "How was this checked?" section. |

**Severity note:** the frontend colours `Critical` red, `Medium` amber and `Low` green. Any other string (for example `"High"`) is shown in neutral grey with the raw text. It is not hidden or remapped. If the matrix has more levels than these three, tell us the full list **[OPEN]** and we will add them.

**Ordering:** findings are not assumed to be sorted. The frontend does not treat `findings[0]` as the most serious.

### 4.4 `evidence_image` **[OPEN]**

The frontend needs to show the audit evidence with faces masked. Options, in order of frontend preference:

| Option | What you send | What the frontend does |
|---|---|---|
| A (preferred) | `evidence_image: null` or absent, and the faces-masked version is provided as a URL (see B) | Draws SVG overlays itself from the polygons |
| B | `"evidence_image": { "url": "https://.../masked.png" }` | Displays that masked image as the base layer and draws SVG overlays on top. Same dimensions and aspect ratio as the original. |
| C | `"evidence_image": { "base64": "...", "mime": "image/png" }` | Same as B, decoded from base64 |

Whichever we choose, the masked image must have **exactly the same aspect ratio as the original**, otherwise normalised polygons will not line up. Please confirm which option and whether masking is already applied. Until this is agreed, the frontend displays the original with overlays and shows a note that masking is done by the backend.

## 5. Validation the frontend performs

The frontend rejects a response, shows an error, and never renders a partial audit if any of these fail:

- Required fields missing or wrong type
- Any coordinate outside `0` to `1` or not a number
- A polygon with fewer than 3 points
- `helmet` or `vest` not in `present` / `absent` / `unknown`
- `zone_id` that is neither `null` nor the `id` of an entry in `zones`
- Duplicate person `id`s
- `image.width` or `image.height` not a positive integer

---

## 6. Errors

Return a non-2xx status with a JSON body so the frontend can show a useful message:

```json
{ "error": { "code": "SEGMENTATION_FAILED", "message": "Could not process the image. Please try again." } }
```

| Status | Meaning | Frontend behaviour |
|---|---|---|
| `400` | Bad request (invalid zones JSON, unsupported file type) | Shows the message, no retry |
| `413` | Image too large | Shows the message |
| `422` | Image readable but could not be audited | Shows the message |
| `429` | Rate limited | Shows the message, offers Retry |
| `500` / `502` / `503` | Server or upstream (Meta API) failure | Shows an error state with Retry |
| Timeout | No response within 60 s (frontend limit) **[OPEN: is 60 s enough?]** | Shows an error state with Retry |

The frontend never shows a fake success after an error.

---

## 7. What is stale, and when

Results belong to one image plus one set of zones. When the operator changes the image or edits any zone, the frontend clears the audit result, review decisions and selection. The backend is stateless from the frontend's view. Review decisions (Reviewed / Needs human review) are kept in the browser for the MVP and are **not** sent back to the backend.

## 9. Change policy

- Additive changes (new optional fields) are fine at any time. Tell the frontend and it will ignore or adopt them.
- Breaking changes (renamed or removed fields, changed meanings, new required fields) need agreement from both people and must land before **Sat 31 Oct**.
- After the freeze, any change goes through a quick message to the other person first, so the demo never breaks on the last day.

---

## 10. Local development without a backend

The frontend runs standalone in fixture mode:

```
npm install
npm run dev
```

In fixture mode the UI loads bundled sample images with matching sample audits and shows a persistent "SAMPLE DATA - not a real audit" banner. To use the real backend later, set:

```
VITE_AUDIT_MODE=backend
VITE_API_BASE_URL=http://localhost:8000
```
